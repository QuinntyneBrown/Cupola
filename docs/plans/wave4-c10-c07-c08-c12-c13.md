# Wave 4 — Implement C07, C08, C10, C12, C13 via ATDD

## Context

Cupola re-implements Open MCT (Angular 21 zoneless frontend + .NET 8 backend), built capability-by-capability per `docs/capability-development-order.md`. Waves 1–3 (C01, C04, C05, C16, C02, C15, C06, C03, C14) are merged. This plan delivers **Wave 4**: C10 conditions/derived-telemetry/filtering, C07 plots, C08 tables/gauges/datum, C12 planning/timelines, C13 notebooks/annotations — **94 L2 requirements** total (specs in `docs/specs/C{07,08,10,12,13}-*.md`, sequence designs in `docs/detailed-designs/C{07,08,10,12,13}-*/`).

**User-approved delivery:** single branch `capability/wave4-c10-c07-c08-c12-c13`, shared contract/enabler commits first, then **one `feat(cNN): … via ATDD` commit per capability**, one PR to `main`. Full coverage of all 94 L2s. No `docs/plans/` records — the detailed plan lives in each commit body (wave-3 precedent, incl. `FLAGGED (out-of-ownership touches):` and `Gates:` sections).

**Why the sequencing matters:** two skeleton contracts C10 owns are empty placeholders on main — `core/src/lib/models/telemetry-filter.ts` (B08) and `conditional-style.ts` (B09) — and `DomainObject` has **no `configuration` field** (backend C# record silently drops unknown JSON), so nothing in the wave can persist view/condition/plan/notebook config until a B01 extension lands. Contract commits must precede capability commits (contracts §5a).

## Cross-cutting conventions (all capability commits)

- **ATDD:** Jest acceptance specs written FIRST, co-located, `describe('OMCT-CNN-L2-XX.YY <Title>')`; every one of the 94 L2s maps to a named Jest spec (mappings enumerated in the sub-plans above) AND appears in exactly one e2e file per L1 (`frontend/e2e/tests/cNN-0L-<slug>.spec.ts`) with `{ annotation: [{ type: 'requirement', description: 'OMCT-…' }] }`, using `../support/cupola.fixture`.
- **Wiring:** each capability ships its own `register-*.ts`; `app.config.ts` gets one line per capability, inserted **before `registerDefaultActions()`** (CreateActions are minted from `TypeRegistry.listCreatable()` at registration).
- **Registered-type keys must match across capabilities:** C07's bar policy rejects `condition-set` (C10's key); C12's strip policy references `overlay-plot` and plot view keys (C07).
- **Flagged out-of-ownership touches** (documented in each commit body, wave-3 style): `app.config.ts`, `core/public-api.ts` + other barrels, `actions/create/creatable-type.ts` (C03), e2e fixtures/support/pages (C16), `SeedData.cs`/`InMemoryObjectStore.cs` (C04), commit-4 B06 telemetry surfaces (C06).
- **e2e fixture isolation:** every capability's fixture objects live in their own new folder; keep all existing `data-testid`s (`plot-view`, `table-view`, `styles-inspector`) — c15 specs assert them.
- **No new npm/NuGet dependencies anywhere** (1 MB build budget; SVG-native charts; no chart.js, no rasterization lib).

2. **`DefaultMetadataProvider` numeric-range wrinkle:** eligibility checks must AND the hints check or every object (incl. images) becomes plottable.
