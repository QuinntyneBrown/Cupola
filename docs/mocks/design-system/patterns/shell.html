Application shell

The frame every screen lives in: app bar, browse tree, main view, inspector, time conductor, and status bar. The shell mounts into a supplied element (OMCT-C01-L2-02.02), exposes the full capability API surface to plugins (OMCT-C01-L2-01.02), and drives everything below the app bar from the hash route and the selection model (OMCT-C15-L1-01).

Numbered regions are specified in the table that follows. Panes are borderless inside the shell — the void canvas shows through 5px splitters, which highlight cyan on hover and drag to resize.

Routing & URL behavior#

Everything the shell shows is reachable by URL. The router dispatches matching hash-path changes to registered handlers, aborts in-flight telemetry requests, and emits the path-change event (OMCT-C15-L2-01.01). Search parameters after the hash carry view and time state and can be set, deleted, or replaced without a navigation (OMCT-C15-L2-01.02). 

// Browse route: each segment is an object identifier, resolved left to right.
// The document title becomes the browsed object's name (OMCT-C15-L2-01.03).
#/browse/mine/station-displays/solar-array-output?view=plot-overlay&tc.mode=local

// Root redirect: /browse forwards to the last child of root composition
// (OMCT-C15-L2-01.04).
#/browse  →  #/browse/mine
Angular provideRouter(routes, withHashLocation()); a resolver walks the identifier path, then Title.setTitle(object.name). Query params are read and written through Router.navigate with queryParamsHandling: 'merge'.

Selection model#

One selection service backs the whole shell. Selecting an element (a plot series, a layout frame, a table row) updates the selected collection, annotates the DOM with s-selected on the element and s-selected-parent on its container, and emits a selection-change event that the inspector and toolbar listen to (OMCT-C15-L2-01.05). Ctrl/Cmd-click multi-selects within one context. 

<section class="cp-editable-canvas" s-selected-parent>
  <div class="cp-frame is-selected" s-selected>…</div>  <!-- inspector shows this -->
</section>

View resolution & priority#

When an object is navigated to, the view registry returns every provider whose canView is true for the object and its path, ordered by descending priority (OMCT-C15-L2-02.01). The URL's requested view wins when applicable; otherwise the highest-priority provider renders. Created views carry their provider key and record their parent element before show runs (OMCT-C15-L2-02.02), which is what makes the large-view overlay below possible.

Large-view overlay#

An embedded view (a frame inside a layout, a plot in a stacked view) expands into a large overlay without navigating; closing it restores the embedded state (OMCT-C15-L2-02.06). Escape dismisses.

The large-view action mounts a preview container in an overlay on the z-overlay layer; destroying the overlay restores the embedded view's state (OMCT-C15-L2-02.06).

Grand search#

The app-bar search field queries indexed objects and annotations as the operator types (OMCT-C15-L2-05.05). Results group by kind; matched substrings highlight in accent. Enter navigates to the focused result; annotation results open the owning object with the annotation targeted.

About dialog & branding#

Activating the app-bar logo opens the about dialog in a large overlay with build and license information (OMCT-C15-L2-05.04). Logo image and dialog content come from the branding options plugins can configure (OMCT-C15-L2-05.03).

Device classes & mobile behavior#

A device classifier stamps the <body> with classes for the detected device, orientation, and touch support (OMCT-C15-L2-05.01). Styles adapt from those classes only — no user-agent branching in components.

Body classApplied whenShell adaptation
desktopPointer-first, wide viewportFrame as mocked above; hover states active.
tabletTablet-class deviceInspector collapses by default; splitters gain a wider hit area.
phonePhone-class deviceTree becomes a drawer, search goes full-screen, conductor edits in a sheet (below).
portrait / landscapeCurrent orientationPane stacking direction on tablet.
touchTouch input presentRow heights grow to 40px; hover-only affordances get persistent equivalents.

The mobile smoke suite (OMCT-C16-L2-03.04) mandates four behaviors on iPad landscape and iPhone-class WebKit viewports: the tree remains reachable as a drawer, search navigation works full-screen, conductor bounds stay editable, and removal always confirms.

Phone-class adaptations

  • Tree → drawer. The browse pane leaves the flow and slides over a scrim from the app-bar toggle; selecting a node navigates and closes it.
  • Search → full-screen. The search icon replaces the inline field; results take the whole viewport with the same object/annotation grouping.
  • Conductor editing. The compact strip shows mode and clock only; tapping opens a full-screen sheet with the complete bounds controls.
  • Removal confirms. Every destructive action raises the confirm dialog — no swipe-to-delete without confirmation.
