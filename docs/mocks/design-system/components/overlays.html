Dialogs & overlays

One overlay service shows any view above the shell (OMCT-C15-L2-04.03): confirmations, forms, selection overlays, progress, and full-screen views share the same surface, scrim, and dismissal rules. Notifications layer on top — banners, snackbars, and the bell panel — with severity semantics borrowed from telemetry, never invented per message.

Dialog anatomy & sizes#

Every dialog is three regions: a head (type icon, title, close button), a body in secondary ink, and a foot with actions right-aligned, affirmative last. Width is the only size variable — height fits content up to 90% of the viewport, then the body scrolls.

Overlay stacking & dismissal#

  • Stacking: overlays stack in opening order; each new overlay renders above the previous with its own scrim. When a full-screen overlay opens above existing dialogs, the covered overlays auto-hide and are restored intact when it closes (OMCT-C15-L2-04.04).
  • Escape and scrim click dismiss only the topmost dismissible overlay — dismissal is strictly last-in-first-out. Dialogs with unsaved input confirm before closing.
  • Non-dismissible overlays (the licenses overlay, blocking progress) ignore Escape and scrim clicks; their only exit is the explicit control they render, or the dismiss handle returned to the code that opened them (OMCT-C16-L2-06.03).

Progress dialogs#

Long operations report through a small progress dialog (OMCT-C14-L2-04.03). Determinate when the total is known — bar, percentage, and a counted message — indeterminate otherwise. The dialog renders no close control: the dismiss handle is returned to the caller, which closes it when the operation settles (or swaps in an error banner).

About dialog#

The About dialog identifies exactly what is running: version, build date, revision, and branch in mono (OMCT-C16-L2-06.01/06.02), reachable from the app menu (OMCT-C15-L2-05.04). The licenses link opens a full-screen overlay of third-party license texts that only its own Done button dismisses (OMCT-C16-L2-06.03).

Notification banners#

Banners are the persistent notification surface, pinned above the affected region. Severity reuses status semantics: info and success auto-dismiss after a timeout (OMCT-C14-L2-04.01); caution and critical persist until the operator dismisses them (OMCT-C14-L2-04.02). Every banner is icon + strong lead + plain sentence + dismiss button — the icon makes severity legible without color.

Time conductor updated. Now following real time, 18:12:04–18:22:04 UTC.
Export complete. 5 objects written to station-power.json.
Ku-band link degraded. Telemetry updates may lag until next acquisition of signal.
Couldn't save. This object was changed by someone else while you were editing. Your values are kept — review the newer version, then retry.
Info · success (auto-dismiss ~5s, OMCT-C14-L2-04.01) · caution · critical (persist until dismissed, OMCT-C14-L2-04.02). The critical example is the save-conflict banner (OMCT-C04-L2-02.07) — it never discards the operator's input.

Snackbars#

Snackbars confirm completed low-stakes actions from the bottom-left and auto-dismiss. At most one shows at a time; a second replaces the first. Anything an operator must act on is a banner, not a snackbar.

Notification list#

Dismissing a banner doesn't destroy it: the bell indicator in the status bar keeps the session's notification history. Its panel lists severity, message, and timestamp, newest first, with a single Dismiss all (OMCT-C14-L2-04.04).

Tooltips#

Two kinds: text tooltips name a control; data tooltips add one mono line — an object path, or a value with its timestamp. Exactly one tooltip is visible at a time (OMCT-C15-L2-04.05); showing a new one hides the previous. Tooltips appear on hover and on keyboard focus, and Escape hides them.
