Browse vs. edit mode#

Entering edit opens one transaction over everything the operator touches. Save commits and stays in edit; Save and finish editing commits and returns to browse; Cancel rolls every dirty object back at once (OMCT-C02-L2-02.07). If a commit fails — conflict, provider offline — the editing session stays open with all values retained so the operator can retry, not retype (OMCT-C03-L2-01.05).

Edit-mode contextual toolbar#

Selecting frames in a display layout aggregates a second toolbar from every provider that applies to the selection (OMCT-C15-L2-03.05). The clusters below act on geometry the layout persists — position, dimensions, rotation, stacking order (OMCT-C09-L2-01.03).

Editing 3 frames selected
Clusters, left to right: align & snap (Snap to grid — pressed, Align to first selected) · distribute (Distribute evenly) · stacking (Stacking order, Bring forward, Send backward) · rotate (Rotate 90°) · clipboard (Copy selection — Paste enables once the layout clipboard holds an item). Interactive: click Snap to grid.

Every icon button carries a tooltip with its exact verb. Controls a provider doesn't offer for this selection simply aren't there; controls that apply but can't run yet are disabled in place.

The Tabs view object#

A Tabs view is a composed object: one tab per child, in composition order, each tab wearing its child's type glyph (OMCT-C09-L2-03.01). Inactive tab views unmount unless the object's eager-load / keep-alive option is set — set it for plots that must keep history, leave it off for imagery that would stream in the background (OMCT-C09-L2-03.02).
